## AI가 틀린 것과 내가 고친 것

오늘은 내가 코드 diff를 직접 고친 일은 없다. AI가 틀렸거나 부족했던 것은 다음과 같다.

1. **AI가 제안한 필수 신뢰도 플래그 2개가 실제 데이터와 맞지 않았다.**
   - 무엇이 틀렸나: Claude는 0012에서 필수 플래그를 "정답이 빈 결과"와 "정답이 값 하나"로 제안했고, 나는 그대로 받아들였다.
   - 어떻게 알았나: 데이터를 넣은 뒤 Claude가 정답 432개를 실행해 보니, 빈 결과는 0개이고 값 하나(1행 1열)는 247개(57%)였다. 빈 결과 플래그는 시연할 사례가 없고, 값 하나 플래그는 조건 없이 걸면 절반 넘게 떠서 의미가 없다.
   - 상태: 아직 고치지 않았다. D19(11/11)에서 다시 정한다. 후보는 "값 하나 + 구조가 크게 다른데 정답 처리" 같은 조건을 붙인 플래그, 또는 `dev_tied_append.json`을 쓰는 동점 대체 정답 플래그다.
2. **승인 전에 커밋·push가 일어났다.**
   - 무엇이 틀렸나: 원래 규칙은 "사용자 승인 없이 커밋하지 않는다"인데, 클라우드 세션의 종료 검사가 커밋·push를 강제해서 ADR 0001~0008 등이 승인 전에 작업 브랜치에 올라갔다.
   - 어떻게 했나: Claude가 매번 사실대로 알렸다. `CLAUDE.md`에는 "강제될 때는 작업 브랜치에만 올리고 알린다. `main`은 PR로만 바꾼다"는 규칙을 넣었다. 이 규칙은 아직 내가 명시적으로 승인하지 않았다.
3. **push 위치를 설명하지 않아 헷갈렸다.**
   - 무엇이 틀렸나: Claude가 PLAN.md를 작업 브랜치에 push하면서 `main`에는 반영되지 않는다는 점을 분명히 말하지 않았다.
   - 어떻게 알았나: 내가 GitHub `main`을 보고 "푸쉬 안 했어?"라고 물었다.
   - 어떻게 고쳤나: PR #1로 merge했다.
4. **Claude가 커밋 전에 스스로 잡은 것** (`examples/bird-mini/download_full_dev.py`)

## 배운 것

모르는 채로 추천을 따른 결정은 `/explain`으로 복습해야 한다.

- **uv:** 가상환경과 `uv.lock`으로 어디서나 같은 버전을 설치한다. `uv sync`, `uv run`, `uv build`
- **Ruff:** 린트(버그가 될 코드 찾기)와 포맷(모양 통일)
- **타입 검사(pyright):** 실행 전에 실수를 찾는다. 예: `Correct`에는 없는 `facts`에 접근하는 코드, 새 상태를 추가했을 때 처리하지 않은 곳, `None`일 수 있는 예측 SQL
- **pytest / Hypothesis / syrupy:** 예시 테스트 / "항상 성립해야 하는 규칙"을 무작위 입력으로 검사 / 긴 출력물 통째로 비교. 판정 코드가 틀리면 연구 결과가 틀리므로, 테스트가 평가 도구의 무결성을 지킨다.
- **BIRD dev의 `dev_tied_append.json`:** 동점을 하나만 고르는(`LIMIT 1`) 정답 대신 동점을 모두 돌려주는 대체 정답 42개다. 정답이 하나가 아닐 수 있다는 판정 신뢰도 문제의 실제 사례다.
- **CI의 Action을 커밋 SHA로 고정하는 이유:** 태그가 바뀌어도 같은 코드가 실행되게 하려고. 공급망 공격 방지
- **`CLAUDE.md`의 `@AGENTS.md`:** 이렇게 가져오면 하나의 규약 파일을 여러 도구가 함께 쓸 수 있고, 두 번 읽히지 않는다.
