# 0005. 대표 기능은 결정적 오답 사실 추출, 부대표는 실행 비교로 한다

- 날짜: 2026-11-04 (기록: 2026-11-07)
- 상태: 채택, 카테고리 매핑 파일 부분은 대체됨(0042)
- 결정자: 사용자
- AI 관여: 선택지 조사·추천 (Claude 추천: 사실 추출 대표, 채택 여부: 예 / Claude가 제안한 후보 coverage 기능은 기각됨)
- 관련 결정 ID: D4

## 맥락
사용자가 연구에서 가장 시간을 많이 쓴 곳은 실행이 아니라 판단이었다. 오답을 하나씩 읽고, 틀린 곳을 찾아 엑셀에 적고, 카테고리를 붙이고, 두 실험의 차이를 손으로 비교했다. 오답 분류를 LLM에 맡기는 것은 평가의 무결성 때문에 받아들이기 어려웠고, 연구마다 오답 카테고리가 달라 합의된 체계도 없다. Claude는 네 가지 후보(판정 신뢰도 플래그, 결정적 사실 추출, 실행 비교, 후보 coverage와 선택 손실)를 제시했다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| 결정적 사실 추출 | 가장 큰 수작업을 대체, AI 없이 근거를 보여줌, 다른 도구에 드묾 | 가장 어렵고 시간이 많이 듦, 구조가 달라도 정답인 SQL을 다뤄야 함 |
| 실행 비교 | 엑셀 비교를 대체, 통계 검정으로 노이즈 판단 | 단독으로는 차별점이 약함 |
| 후보 coverage와 선택 손실 | 생성·선택 중 병목을 숫자로 보여줌 | 구현이 쉬움, 다중 후보는 필수 요소가 아님 |

## 결정
대표 기능은 결정적 오답 사실 추출, 부대표는 실행 비교로 한다. 후보 coverage는 이번 범위에서 뺀다. 판정 신뢰도 플래그는 두 기능을 보조하는 범위로 구현한다.

## 이유
결정적 사실 추출을 대표, 실행 비교를 부대표로 한다. 후보 coverage는 구현이 쉽고, multi-candidate가 text-to-SQL 모델의 필수 요소가 아니어서 뺀다. 구조가 달라도 올바른 답을 내는 SQL이 충분히 있을 수 있으므로, 사실 추출 로직은 깊게 함께 설계한다.

도구가 사실을 보고하는 것만으로도 크게 도움이 된다. 틀린 케이스를 하나씩 찾아 비교하고, 엑셀에 적고, 카테고리를 붙이는 일이 줄어든다. NL이나 SQL이 길고 읽기 힘들어 분석이 어려운 문제도 덜어진다.

## 결과
- 도구는 "무엇이 다른가"를 사실로만 보고하고, "왜 틀렸나" 카테고리는 사용자가 매핑 파일로 정한다(D20). → 매핑 파일은 로드맵으로 미룸, 사용자 분류는 CSV의 `my_category` 열로 한다(0042).
- 사실 목록과 정규화 규칙은 실제 오답 케이스를 보며 별도 설계 세션에서 정한다(D18).
- 후보 coverage는 로드맵에 둔다(0008).
