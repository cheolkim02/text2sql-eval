# 0050. ponytail은 항상 적용하되, AGENTS.md가 우선하고 보고는 한국어로 한다

- 날짜: 2026-11-20
- 상태: 채택
- 결정자: 사용자
- AI 관여: 우리 규칙과 부딪히는 곳 조사와 선택지 추천 (Claude 추천: 항상 적용, AGENTS.md 우선, 보고는 한국어, 채택 여부: 예)
- 관련 결정 ID: D46

## 맥락
ponytail(0049)은 모든 코딩 작업에 항상 적용되도록 쓰여 있고, `audit`·`review`는 아주 쉬운 영어로 보고한다. 이 저장소의 `AGENTS.md`에는 결정 절차, 한국어 보고, 파일 5개 단위의 작업 순서가 있다. 둘이 다를 때 어느 쪽을 따를지 정해야 했다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| 항상 적용, `AGENTS.md`가 우선, 보고는 한국어 | ponytail 원칙이 모든 작업에 적용되면서 결정 절차는 그대로 | 원본과 조금 다르게 동작함 |
| `/ponytail`을 부를 때만 적용, `AGENTS.md`가 우선, 보고는 한국어 | 평소 작업에는 영향이 없음 | 정리할 때만 적용되고, 복사한 skill을 고쳐야 함 |
| 원본 그대로 | 손댈 것이 없음 | 영어로 보고하고, 결정 절차와 겹칠 때 기준이 없음 |

## 결정
ponytail을 모든 코딩 작업에 적용한다. `AGENTS.md`와 다르면 `AGENTS.md`를 따른다. `/ponytail-review`와 `/ponytail-audit`의 보고는 한국어로 쓰고, 형식은 원본을 따른다. 이 내용은 `AGENTS.md`의 "ponytail" 절에 적는다.

## 이유
추천안(항상 적용, `AGENTS.md` 우선, 보고는 한국어)을 채택했다. ponytail의 원칙(이미 있는 것을 먼저 쓰고, 요청하지 않은 추상화를 만들지 않음)은 `review` 체크리스트와 같은 방향이라 항상 적용해도 충돌이 적다. 규칙의 우선순위만 분명하면 된다.

## 결과
- `AGENTS.md`에 "ponytail" 절을 더한다. 특히 다음은 ponytail과 다르게 이 저장소의 규칙을 따른다.
  - ponytail이 빼거나 줄이자고 하는 것이 결정 대상이면, 결정 절차로 사용자에게 묻는다.
  - 작업 단위(계획 승인, 테스트, `check.sh`, `review` 자가 검토, 파일 5개 이하)는 그대로다.
  - ponytail의 `shortcut:` 주석은 다른 주석처럼 영어로 쓴다.
- `CLAUDE.md`의 skill 목록에 세 skill을 더한다.
- 복사한 skill 파일은 고치지 않는다.
