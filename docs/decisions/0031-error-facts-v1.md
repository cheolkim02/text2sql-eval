# 0031. 오답 사실 1차: 결과 카테고리 5개와 구조 사실 4종

- 날짜: 2026-11-10
- 상태: 채택
- 결정자: 사용자
- AI 관여: 실제 오답 161건을 결과 차이로 분류해 7개 카테고리를 제안 (Claude 제안: 결과 카테고리 7개, 구조 사실은 다음 단계로. 채택 여부: 부분 채택. 사용자가 7개를 5개로 합치고, 구조 사실 4종을 이번 범위에 넣음)
- 관련 결정 ID: D18

## 맥락
대표 기능(0005)은 오답에서 "무엇이 다른가"를 AI 없이 근거와 함께 보여 주는 것이다. 2026-11-10 사실 설계 세션에서 gpt-4o-mini evidence 있음 실행(0028)의 오답 161건을 실행 결과 기준으로 나눴다.

| 결과 차이 | 건수 |
| --- | --- |
| 값 하나짜리 결과가 다름 | 44 |
| 예측 컬럼이 더 적음 | 32 |
| 예측 컬럼이 더 많고 정답 결과를 포함 | 25 |
| 예측 결과가 비어 있음 | 24 |
| 같은 폭, 겹치는 행 없음 | 13 |
| 예측이 정답의 부분집합 / 초집합 | 8 / 8 |
| 예측 컬럼이 더 많고 정답 결과를 포함하지 않음 | 5 |
| 일부만 겹침 | 2 |

또 정답 판정 267건 중 257건(96%)은 SQL 문장이 정답과 달랐다. 구조 차이는 정답 케이스에서도 흔하므로, 구조 사실은 오답에만 낸다.

| 안 | 장점 | 단점 |
| --- | --- | --- |
| 결과 카테고리 7개, 구조 사실은 다음 단계 | 파서 없이 이번 주 안에 확실히 동작 | "왜 틀렸나"에 가까운 정보가 없음 |
| 결과 카테고리 5개 + 구조 사실 4종 (채택) | 큰 분류는 결과로 확실히, 원인 힌트는 구조로 | 파서 의존성과 정규화 작업이 필요 |
| 세분화된 구조 사실 전체 (계획서 초안) | 가장 상세 | 일정 안에 끝나지 않을 위험 |

## 결정

**1. 결과 카테고리 (오답마다 정확히 하나, 위에서부터 먼저 맞는 것)**

| 코드 | 조건 | 한국어 설명 (리포트용) |
| --- | --- | --- |
| `execution_failed` | 예측 SQL이 오류·시간 초과·행 제한으로 실패 | 실행 실패 |
| `empty_result` | 예측 결과가 0행이고 정답은 0행이 아님 | 빈 결과 |
| `column_mismatch` | 컬럼 수가 다름 | 컬럼 구성 차이 |
| `single_value_differs` | 둘 다 1행 1열인데 값이 다름 | 값 하나가 다름 |
| `row_set_differs` | 그 밖의 모든 경우 (같은 폭, 행 집합이 다름) | 행 집합 차이 |

`column_mismatch`와 `row_set_differs`에는 보조 정보를 붙인다: 정답 결과가 예측 결과 안에 그대로 들어 있는지(컬럼 부분집합으로 사영했을 때 행 집합이 같은지), 예측이 정답의 부분집합·초집합인지. 이 정보는 거짓 오답 의심 플래그(D19)의 재료가 된다.

**2. 구조 사실 (오답에만, sqlglot으로 정답·예측 SQL을 파싱해 비교)**

| 코드 | 보고하는 것 | 근거 |
| --- | --- | --- |
| `where_value` | WHERE 비교 조건의 값(리터럴)이 다름 | 정답 쪽 조건, 예측 쪽 조건 |
| `tables_joins` | 사용한 테이블 집합 또는 JOIN 수가 다름 | 정답에만·예측에만 있는 테이블, JOIN 수 |
| `aggregation` | 집계 함수(COUNT, SUM, AVG, MIN, MAX)의 집합이 다름 | 양쪽 집계식 |
| `order_limit` | ORDER BY 또는 LIMIT의 유무·내용이 다름 | 양쪽 절 |

정규화는 최소한만 한다: 대소문자, 공백, 끝의 세미콜론, 별칭(테이블 별칭을 실제 이름으로 치환). 그 이상(조건 순서, `IN` ↔ `EXISTS`, 서브쿼리 ↔ JOIN)은 다음 단계다.

**3. 파서:** sqlglot (D15). 2026-11-10 기준 30.31.0, MIT, 의존성 0개. baseline 두 실행의 SQL 1,728개 중 1,727개를 파싱했고, 유일한 실패는 SQLite도 거부하는 깨진 쿼리라 `execution_failed`로 먼저 잡힌다.

**4. 정답 케이스에는 사실을 내지 않는다.**

## 이유
> "우선 지금은 복잡하게 만들지 말고, 기본적인 카테고리화정도만 하자. 일단 큼직하게 만들고, 디테일하게, 세분화된 카테고리들은 나중에 이게 deliverable하게 만들어진 후에 기능을 추가해도 돼. 정답인 것들은 따로 카테고리화 안할거야. 틀린 문제들만."
>
> "이 7개에서 3,4 합치고, 6,7 합쳐. Sql 구조도 지금 하자. 지금 네가 보여준 4개. 파서는 sqlglot."
>
> "이름은 영어, 레포트에 한국어 설명."

## 결과
- sqlglot이 첫 런타임 의존성이 된다(0019의 "첫 런타임 의존성 자리는 SQL 파서"대로).
- 결과 카테고리는 결정적이고 파서와 무관하다. 구조 사실은 파싱 실패 시 생략하고 그 사실을 기록한다.
- 세분화(WHERE 컬럼·연산자, GROUP BY, SELECT 컬럼, DISTINCT, 서브쿼리)는 deliverable이 된 뒤 로드맵으로 다룬다.
- 계획서의 범위 축소 규칙(11/9 밤 점검)은 이 결정으로 대체한다.
