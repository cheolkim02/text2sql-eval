# 0003. 구현 언어를 Python으로 한다

- 날짜: 2026-11-04 (기록: 2026-11-07)
- 상태: 채택 (계획서 초판의 TypeScript를 대체)
- 결정자: 사용자
- AI 관여: 선택지 조사·추천 (Claude 추천: Python, 채택 여부: 예)
- 관련 결정 ID: D2

## 맥락
계획서 초판은 토스 서류 지원 가이드의 "TypeScript를 정확하게 사용하기 위해 고민한 리포지토리면 좋아요" 항목에 맞춰 TypeScript를 골랐다. 그러나 사용자는 TypeScript를 써 본 적이 없고, 대표 기능(오답 사실 추출, 0005)은 SQL 파싱·정규화 라이브러리의 품질에 크게 좌우된다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| TypeScript | 가이드의 TypeScript 항목을 글자 그대로 채움 | 사용자가 처음 쓰는 언어, SQL 정규화 생태계가 약해 직접 만들어야 할 부분이 많음, 모든 줄을 설명하기 어려움 |
| Python | 사용자가 익숙함, sqlglot 등 방언 파싱·정규화 도구가 성숙함, 사용자층(text-to-SQL 연구자)과 BIRD 공식 평가 스크립트가 Python | 가이드의 TypeScript 항목은 글자 그대로는 채우지 못함 |

## 결정
Python으로 구현한다.

## 이유
> "솔직히 typescript가 아니어도 무방하다고 생각하기도 해."
>
> "typescript가 꼭 필요할지 모르겠어. 말한 것처럼. 공고에도 typescript라는 단어도 딱 한번밖에 안 나오고, 그냥 repository 기준에 "TypeScript를 정확하게 사용하기 위해 고민한 리포지토리면 좋아요." 라고 써있는거 뿐이야."
>
> "Python으로 가자."

보충: 가이드 7개 항목 중 6개는 언어와 무관하다. 마지막 항목의 취지(타입을 정확하게 쓰려는 고민)는 Python의 strict 타입 검사, `Literal` 기반 판별 유니언, `py.typed` 배포로 보여준다.

## 결과
- 패키지는 `src/text2sql_eval/` 하나로 둔다.
- 타입 검사기 strict 모드 0 오류를 완료 기준에 넣는다(타입 검사기는 D11에서 정함).
- 토스 과제 전형이 TypeScript일 가능성에 대비해, 서류 제출 뒤(11/16~19) TypeScript 기초를 따로 학습하는 것을 권장 일정으로 둔다.
