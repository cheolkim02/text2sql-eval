# 0035. 실행 비교에 통계 검정(McNemar)을 넣지 않는다

- 날짜: 2026-11-11
- 상태: 채택
- 결정자: 사용자
- AI 관여: McNemar 정확 검정을 직접 구현하는 안을 추천하고 실제 데이터로 예시를 계산함 (Claude 추천: 정확 검정 직접 구현, 채택 여부: 아니오)
- 관련 결정 ID: D22

## 맥락
계획서는 `compare`가 두 실행의 차이가 노이즈인지 McNemar 검정으로 알려 주도록 했다. 2026-11-11 baseline 두 실행에 계산해 보면, 엇갈린 케이스가 18 대 123으로 p = 2×10⁻²⁰이었다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| McNemar 정확 검정 직접 구현 | 의존성 0개, 작은 차이가 노이즈인지 알려 줌 | 사용자가 연구에서 쓰지 않았고, text-to-SQL 평가 관행에서 거의 쓰이지 않음 |
| scipy로 구현 | 검증된 구현 | 설치가 무거움 |
| 넣지 않음 | 범위가 줄고, 연구 관행(EX와 케이스 단위 비교)에 맞음 | 작은 EX 차이의 의미를 수치로 판단해 주지 않음 |

## 결정
`compare`는 통계 검정을 하지 않는다. 분할표(둘 다 맞음, 한쪽만 맞음, 둘 다 틀림), 뒤집힌 케이스 목록, 차이 분포 변화에 집중한다.

## 이유
> "McNemar는 내가 써본것도 아니고, 이게 실제 nl2sql 연구 평가에서 중요하지 않는 부분 같아서, 이건 안하고 싶은데"

## 결과
- 계획서, `AGENTS.md`, 폴더 구조와 가이드 목록에서 McNemar를 뺀다.
- 분할표의 엇갈린 칸(한쪽만 맞음) 숫자는 그대로 보여 주므로, 필요하면 사용자가 직접 검정할 수 있다.
- 통계 검정은 로드맵에 둔다.
