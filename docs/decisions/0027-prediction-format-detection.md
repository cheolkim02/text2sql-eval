# 0027. 예측 파일 형식은 확장자로 판별하고, 옵션으로 덮어쓸 수 있게 한다

- 날짜: 2026-11-09
- 상태: 채택
- 결정자: 사용자
- AI 관여: 선택지 조사·추천 (Claude 추천: 확장자 판별 + 덮어쓰기 옵션, 채택 여부: 예)
- 관련 결정 ID: D32 (0018 후속)

## 맥락
0018에서 예측 파일을 두 형식(한 줄 한 SQL 텍스트, 자체 JSONL)으로 받기로 했고, 둘을 어떻게 구분할지는 CLI 결정 때 정하기로 했다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| 확장자로 판별 + 덮어쓰기 옵션 | 대부분 옵션 없이 동작, 애매하면 안내 | 확장자 규칙을 알아야 함 |
| `--pred-format` 항상 필수 | 가장 명확 | 매번 써야 해서 번거로움 |
| 파일 내용으로 추측 | 옵션 없음 | 추측이 틀리면 원인을 찾기 어려움 |

## 결정
- `.txt`는 텍스트 형식, `.jsonl`은 JSONL 형식으로 읽는다.
- 그 밖의 확장자는 입력 오류로 처리하고 `--pred-format text|jsonl`을 안내한다.
- `--pred-format`을 주면 확장자보다 우선한다.
- JSONL에서 예측이 빠진 케이스를 허용하는 `--allow-missing`을 둔다.

## 이유
> "D32 확장자 판별 + 덮어쓰기 옵션"

## 결과
- `--allow-missing`으로 빠진 케이스는 빈 예측과 같은 방식으로 판정하되(0023), 실행 파일에는 "누락"으로 따로 기록한다.
