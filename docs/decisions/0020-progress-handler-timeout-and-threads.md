# 0020. 쿼리 시간 제한은 SQLite 진행 콜백으로, 병렬 실행은 스레드로 한다

- 날짜: 2026-11-08
- 상태: 채택
- 결정자: 사용자
- AI 관여: 선택지 조사·추천과 실험 (Claude 추천: 진행 콜백 + 스레드 병렬, 채택 여부: 예)
- 관련 결정 ID: D17

## 맥락
모델이 만든 SQL이 끝나지 않으면(예: 무한 재귀 CTE) 평가 전체가 멈춘다. 쿼리마다 시간 제한이 필요하고, 수백~수천 개 쿼리를 빨리 돌리려면 병렬 실행이 필요하다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| 진행 콜백(`Connection.set_progress_handler`) + 스레드 병렬 | 표준 라이브러리만 씀, 쿼리마다 마감 시각 하나로 끝남 | SQLite 내부 연산 하나가 아주 길면 그만큼 늦게 멈출 수 있음 |
| 별도 프로세스, 시간 초과 시 종료 | 가장 강한 격리 | 쿼리마다 프로세스 비용, 결과 전달과 디버깅이 복잡 |
| 감시 스레드 + `Connection.interrupt()` | 표준 라이브러리 | 쿼리마다 타이머 스레드가 필요해 움직이는 부분이 많음 |

## 결정
쿼리마다 마감 시각을 정하고, 진행 콜백이 마감을 넘기면 쿼리를 멈춘다. 병렬 실행은 스레드로 하며, 스레드마다 읽기 전용 연결(`file:...?mode=ro`)을 따로 연다.

## 이유
추천안(진행 콜백 + 스레드 병렬)을 채택했다.

보충: 2026-11-08 이 환경(Python 3.11.18, SQLite 3.45.1)에서 확인한 사실이다.
- 끝나지 않는 재귀 쿼리에 1초 제한을 걸면 1.0초에 `OperationalError: interrupted`로 멈췄다.
- 읽기 전용 연결에서 `DELETE`는 `attempt to write a readonly database`로 막혔다.
- 0.5초 제한 쿼리 4개를 스레드 4개로 돌리면 전체가 0.5초에 끝났다. sqlite3 모듈이 쿼리를 실행하는 동안 GIL을 놓기 때문이다.

## 결과
- 시간 초과는 "실행 오류" 중 하나가 아니라 별도의 `timeout` 결과로 기록한다.
- 시간 기준은 시스템 시계가 아니라 `time.monotonic()`을 쓴다.
- BIRD 공식 평가 스크립트의 시간 제한 방식은 D16에서 원본 코드로 확인하고, 결과가 달라질 수 있는 차이가 있으면 문서에 적는다.
- 진행 콜백이 늦게 멈추는 사례가 실제로 나오면 이 결정을 다시 본다.
