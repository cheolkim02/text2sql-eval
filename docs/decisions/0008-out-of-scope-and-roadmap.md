# 0008. 범위에서 뺄 것과 로드맵으로 미룰 것

- 날짜: 2026-11-04 (기록: 2026-11-07)
- 상태: 채택
- 결정자: 사용자
- AI 관여: 선택지 조사·추천 (Claude 추천: 아래 목록, 채택 여부: 예 / LLM 분석 beta는 사용자 제안)
- 관련 결정 ID: D7
- 편집: 2026-11-15, 공개 전에 프로젝트와 무관한 개인 정보를 지움([0047](0047-remove-unrelated-personal-content.md))

## 맥락
완료 목표일(2026-11-15)까지 하루 약 5시간으로 좁고 깊게 만들어야 한다. 계획서 초판의 범위(패키지 3개, CLI 명령어 10개)는 넓었고, 사용자가 겪지 않은 문제(위험한 SQL 생성, rate limit, 실행 중 중단)를 푸는 기능도 있었다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| 초판 범위 유지 | 보여줄 항목이 많음 | 넓고 얕아지고, 모든 줄을 설명하기 어려움 |
| 겪은 문제에 집중해 줄임 | 대표 기능에 시간을 쓸 수 있음 | 보여줄 항목 수는 줄어듦 |

## 결정
- **뺀다:** `llm-spec` 패키지, SQL 파서 기반 가드(읽기 전용 연결과 시간 제한으로 대신함), LLM 호출·Provider·응답 캐시·mock, `init`·`schema`·`guard`·`cases lint` 명령
- **로드맵으로 미룬다:** PostgreSQL·MySQL 실행 백엔드, 파이프라인 단계별 추적, 사람 라벨과 자동 사실의 일치도, 후보 coverage와 선택 손실, 결과 파일을 LLM이 분석하는 beta, 합성 예제 데이터셋, 실험 추적 도구 연동

## 이유
> "뺄 것과 미룰것 잘 정한거 같아."
>
>
