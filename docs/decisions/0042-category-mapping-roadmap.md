# 0042. 사용자 카테고리 매핑 파일은 로드맵으로 미룬다

- 날짜: 2026-11-12
- 상태: 채택
- 결정자: 사용자
- AI 관여: 선택지 조사·추천 (Claude 추천: 로드맵으로 미룸, 채택 여부: 예)
- 관련 결정 ID: D20

## 맥락
0005는 "왜 틀렸나" 카테고리를 사용자가 매핑 파일(`--categories map.toml`)로 정하도록 했고, 완료 기준에도 들어 있었다. 그 뒤 오답에 출력 차이가 여러 개 붙도록 바뀌었고(0033), CSV에는 사용자가 채우는 빈 `my_category`·`notes` 열이 생겼다(0007). 남은 일정은 필수 항목인 문서에 써야 한다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| 로드맵으로 미룸 | 시간을 문서에 씀, CSV의 `my_category`로 손 분류는 지금도 가능 | 완료 기준을 고쳐야 함 |
| 단순 매핑 구현 (차이 코드 하나 → 내 카테고리) | 계획대로 완료 기준 충족 | 차이가 여러 개인 오답의 규칙과 TOML 형식을 또 정해야 함, 반나절 이상 |

## 결정
매핑 파일과 `--categories` 옵션은 만들지 않고 로드맵에 둔다. 사용자 분류는 CSV의 `my_category`·`notes` 열로 한다.

## 이유
> "D20 로드맵"

보충: 0031에서 사용자가 "세분화된 카테고리들은 나중에 이게 deliverable하게 만들어진 후에 기능을 추가해도 돼"라고 했다.

## 결과
- 0005의 "카테고리는 사용자가 매핑 파일로 정한다(D20)"는 이 결정으로 대체된다.
- PLAN의 완료 기준, 필수 목록, CLI 초안, 폴더 구조에서 매핑 파일을 로드맵으로 옮긴다.
- 다시 볼 조건: 사용자가 CSV로 손 분류한 결과가 쌓여, 차이 코드와 자기 카테고리의 대응이 반복된다고 확인될 때.
