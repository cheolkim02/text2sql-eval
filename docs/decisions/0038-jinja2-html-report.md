# 0038. HTML 리포트는 Jinja2 템플릿으로 만든다

- 날짜: 2026-11-11
- 상태: 채택
- 결정자: 사용자
- AI 관여: 선택지 조사·추천 (Claude 추천: Jinja2, 채택 여부: 예)
- 관련 결정 ID: D21

## 맥락
`report`는 실행 파일 하나를 받아, 오프라인에서 열리는 HTML 파일 하나를 만든다(0007). 화면에는 질문, evidence, SQL, 결과 값처럼 사용자 데이터가 그대로 들어간다. 그래서 `<`, `&`, `'` 같은 문자를 HTML로 안전하게 바꾸는 이스케이프를 빠뜨리지 않는 것이 가장 중요하다. 빠뜨리면 질문에 `<b>`가 있을 때 화면이 깨지고, 악의적인 값이면 스크립트가 실행된다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| Jinja2 3.1.6 (BSD-3-Clause, 의존성 MarkupSafe) | 자동 이스케이프로 누락이 없음, 템플릿이 HTML 모양 그대로라 읽기 쉬움, 가장 널리 쓰는 방식 | 런타임 의존성 2개 추가 (Jinja2, MarkupSafe) |
| 표준 라이브러리 (`html.escape` + 문자열 조립) | 의존성 0개 | 값마다 직접 이스케이프해야 해서 하나만 빠뜨려도 버그, HTML이 Python 코드에 흩어짐 |
| 데이터는 JSON으로 넣고 화면은 JavaScript로 그림 | 의존성 0개, 필터가 빠름 | 화면 로직을 pyright·pytest로 검사할 수 없음, 설명할 언어가 늘어남 |

## 결정
Jinja2로 HTML 템플릿을 렌더링하고, 자동 이스케이프를 켠다. CSS와 필터용 JavaScript는 템플릿 안에 인라인으로 넣어 외부 요청이 없는 파일 하나로 만든다.

## 이유
> "D21. Jinja2."

보충: 이스케이프를 도구가 보장하는 것이 의존성 2개의 비용보다 크다고 보았다. 화면 로직은 Python과 템플릿에 두고, JavaScript는 필터(행 보이기·숨기기)에만 쓴다.

## 결과
- 런타임 의존성이 sqlglot, Jinja2 둘이 된다(MarkupSafe는 Jinja2를 따라 설치된다). 하한은 확인한 버전 `jinja2>=3.1.6`으로 둔다.
- 템플릿 파일은 패키지 안에 두므로, wheel에 템플릿이 들어가는지 CI의 빌드 검사에서 확인한다.
- 이스케이프가 실제로 되는지 `<script>`가 든 질문으로 테스트한다.
- 출처: [PyPI Jinja2 3.1.6](https://pypi.org/project/Jinja2/3.1.6/), [PyPI MarkupSafe 3.0.4](https://pypi.org/project/MarkupSafe/3.0.4/) (2026-11-11 확인)
