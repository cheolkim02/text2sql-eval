# 0021. 쿼리 실행 기본값: 쿼리당 30초, 행 수 제한 없음, 읽기 전용

- 날짜: 2026-11-08
- 상태: 채택
- 결정자: 사용자
- AI 관여: BIRD 공식 평가 코드 확인과 기본값 제안 (Claude 추천: 아래 결정, 채택 여부: 예)
- 관련 결정 ID: D17 후속

## 맥락
실행기의 기본값(시간 제한, 행 수 제한, 동시 실행 수)은 판정 결과에 영향을 준다. 예를 들어 제한보다 오래 걸리는 정답 쿼리는 시간 초과가 된다. 2026-11-08에 BIRD 공식 평가 코드 두 판을 읽고 동작을 확인했다.
- AlibabaResearch/DAMO-ConvAI의 `bird/llm/src/evaluation.py`
- bird-bench/mini_dev의 `evaluation/evaluation_ex.py`, `evaluation_utils.py`

공식 코드의 동작은 다음과 같다.
- **시간 제한:** 기본 30초. 예측과 정답 두 쿼리를 **합친** 실행에 건다(`func_timeout`, 프로세스 풀).
- **연결:** `sqlite3.connect(db_path)`로 **쓰기 가능하게** 연다.
- **행 수:** `fetchall()`로 제한 없이 모두 가져온다.
- **예측이 없을 때:** 공백 SQL `" "`을 실행한다. 결과는 빈 집합이다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| 공식과 같은 값을 쓰되 쿼리마다 따로 재고 읽기 전용으로 연다 | 공식 결과와 거의 같고, 예측 SQL이 DB를 바꾸지 못함 | 두 쿼리 합이 30초를 넘고 각각은 30초 미만인 경우, 그리고 쓰기 쿼리에서 공식과 달라질 수 있음 |
| 공식과 똑같이 (두 쿼리 합 30초, 쓰기 가능) | 공식 결과와 완전히 같음 | 예측 SQL이 시연 DB를 바꿀 수 있고, 정답·예측을 함께 재야 해 실행 구조가 묶임 |
| 더 짧은 시간 제한 (예: 5초) | 빠름 | 공식에서 정답인 느린 쿼리가 시간 초과가 됨 |

## 결정
- **시간 제한:** 쿼리당 30초
- **행 수 제한:** 기본값은 없음. 옵션으로 줄 수 있고, 넘으면 `row_limit` 실패로 기록한다.
- **동시 실행 수:** 기본값은 `min(8, CPU 수)`
- **연결:** 읽기 전용(`mode=ro`)으로 연다.
- **실행 결과:** 성공이면 컬럼 이름과 행, 실패면 `error`·`timeout`·`row_limit` 중 하나로 기록한다.
- **DB 파일이 없을 때:** 입력 오류로 처리하고 `<db-dir>/<db_id>/<db_id>.sqlite` 구조를 안내한다.

## 이유
> "이대로 진행해줘"

## 결과
- 공식 코드와 결과가 달라질 수 있는 두 경우를 `docs/guides/reading-results.md`와 EX 판정 문서에 적는다.
  - 두 쿼리를 합친 시간이 30초를 넘는 경우
  - 쓰기 쿼리
- 빈 예측을 어떻게 판정할지는 EX 판정 규칙(D16)에서 정한다. 공식 코드에서는 정답 결과가 빈 집합이면 정답으로 처리된다.
