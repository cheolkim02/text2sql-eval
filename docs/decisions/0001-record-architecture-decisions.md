# 0001. 설계 결정을 ADR로 기록하고, 라이선스를 코드 MIT·예제 데이터 CC BY-SA 4.0으로 한다

- 날짜: 2026-11-03 (기록: 2026-11-07)
- 상태: 채택
- 결정자: 사용자
- AI 관여: 없음 (사용자가 계획서 초판에서 정함)
- 관련 결정 ID: —

## 맥락
이 저장소는 사람(설계·결정·리뷰)과 AI(선택지 제시·구현·기록)가 함께 만든다. 누가 무엇을 왜 정했는지가 남지 않으면, 나중에 코드를 설명하거나 결정을 다시 볼 때 근거가 없다. 또 저장소에 BIRD 데이터 일부를 함께 배포하므로 코드와 데이터의 라이선스를 구분해야 한다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| ADR 파일로 기록 | 결정마다 맥락·선택지·이유가 남고, 저장소 안에서 리뷰·검색 가능 | 쓰는 비용이 든다 |
| 커밋 메시지에만 기록 | 추가 파일 없음 | 선택지와 기각 이유가 흩어지고 찾기 어렵다 |
| 기록하지 않음 | 빠르다 | AI가 정한 것과 사람이 정한 것을 구분할 수 없다 |

## 결정
설계 결정은 `docs/decisions/NNNN-<slug>.md`에 ADR로 기록하고, 결정자는 항상 사용자로 둔다. 코드는 MIT, `examples/bird-mini`의 데이터는 CC BY-SA 4.0으로 배포한다.

## 이유
계획서 초판(2026-11-03)에서 사용자가 정했다. AI가 구현을 많이 맡는 만큼, 설계 판단이 사람에게서 나왔다는 것과 그 이유를 기록으로 남기는 것이 목적이다. 데이터 라이선스는 BIRD 팀이 공지한 CC BY-SA 4.0을 따른다(0006 참고).

## 결과
- `docs/decisions/0000-template.md` 형식을 따르고, `docs/decisions/README.md`에 색인을 둔다.
- ADR이 필요 없다고 사용자가 답한 변경은 `docs/decisions/skipped.md`에 한 줄로 남긴다.
- 루트 `LICENSE`는 MIT, `examples/bird-mini/LICENSE`는 CC BY-SA 4.0으로 따로 둔다.
