# 0044. CI에서 빌드한 wheel을 깨끗한 환경에 설치해 CLI를 돌린다

- 날짜: 2026-11-12
- 상태: 채택
- 결정자: 사용자
- AI 관여: 2단계 계획에서 선택 항목으로 제시 (Claude 추천: 없음, 넣을지 사용자가 고르도록 함, 채택 여부: 해당 없음)
- 관련 결정 ID: D40
- 편집: 2026-11-15, 공개 전에 프로젝트와 무관한 개인 정보를 지움([0047](0047-remove-unrelated-personal-content.md))

## 맥락
완료 기준에 "새 환경에서 설치 → `eval` → `report`가 3분 안에 됨"이 있다. 지금 CI는 개발 환경(`uv sync`)에서 테스트하고, 빌드 단계는 wheel 안의 파일 목록만 확인한다. 그래서 배포되는 wheel이 실제로 설치되어 돌아가는지는 확인하지 않는다. PLAN 권장 목록 2번(CI 도그푸딩)이 이것이다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| 빌드 단계에서 wheel을 새 가상환경에 설치하고 `eval → report`를 돌림 | 배포물이 실제로 동작하는지 PR마다 확인, 완료 기준을 자동으로 검사 | CI 시간이 조금 늘어남 |
| 넣지 않음 | CI가 그대로 | 템플릿 누락이나 의존성 누락 같은 배포 문제를 늦게 발견 |

## 결정
CI의 빌드 단계에서, 빌드한 wheel을 개발 의존성 없는 새 가상환경에 설치하고 `examples/bird-mini`로 `text2sql-eval eval`과 `report --html --csv`를 실제로 돌린다.

## 이유
> "1~3번 진행하고 4번도 넣어줘"

## 결과
- 개발 의존성 없이 설치된 패키지만으로 CLI가 끝까지 도는지 확인한다(예: 템플릿 파일이나 런타임 의존성 누락).
- 시간을 줄이려고 예측 일부만 쓰고 `--allow-missing`과 짧은 시간 제한을 준다.
