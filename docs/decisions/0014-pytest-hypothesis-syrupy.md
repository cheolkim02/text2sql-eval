# 0014. 테스트는 pytest, Hypothesis, syrupy로 한다

- 날짜: 2026-11-07
- 상태: 채택
- 결정자: 사용자
- AI 관여: 선택지 조사·추천 (Claude 추천: pytest + Hypothesis + syrupy, 채택 여부: 예). 사용자가 도구를 잘 모른다고 밝혀 추천을 따른 결정이다.
- 관련 결정 ID: D12

## 맥락
테스트 도구를 정해야 했다. 이 프로젝트에는 성격이 다른 세 종류의 검사가 필요하다. 함수 하나의 동작(로더, 판정, 비교), 수많은 SQL 변형에 대해 항상 성립해야 하는 규칙(정규화, 판정), 긴 출력물(HTML, CSV, 터미널 요약)이다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| pytest + Hypothesis + syrupy | 세 종류의 검사에 각각 맞는 도구, 모두 Stable 이상 | 개발용 의존성 3개 |
| pytest + Hypothesis | 의존성 하나 적음 | 출력물 비교를 직접 짜야 함 |
| unittest | 표준 라이브러리 | 코드가 장황하고 fixture가 약함 |

## 결정
pytest(테스트 실행), Hypothesis(속성 기반 테스트), syrupy(스냅샷 테스트)를 개발용 의존성으로 쓴다. 커버리지 측정은 이번에 넣지 않는다.

## 이유
추천안(pytest + Hypothesis + syrupy)을 채택했다.

보충: 사용자는 세 도구를 모른다고 밝혔다. 이 결정은 Claude의 추천을 따른 것이고, 각 도구가 무엇을 검사하는지 `/explain`으로 학습해야 한다.

## 결과
- 테스트는 `tests/` 아래에 두고, 실제 SQLite를 쓰는 통합 테스트도 네트워크 없이 돈다.
- 스냅샷이 바뀌면 diff를 사람이 읽고 승인한 뒤에만 갱신한다.
