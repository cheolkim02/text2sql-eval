# 0019. 데이터 모델은 dataclass, 입력 검증은 직접 구현한다

- 날짜: 2026-11-08
- 상태: 채택
- 결정자: 사용자
- AI 관여: 선택지 조사·추천 (Claude 추천: dataclass + 직접 검증, 채택 여부: 예)
- 관련 결정 ID: D13

## 맥락
파일에서 읽은 데이터셋·예측 값을 코드 안에서 어떤 모양으로 다루고, 잘못된 입력을 어떻게 걸러 낼지 정해야 했다. 오류 메시지에 줄 번호와 고칠 방법을 넣는 것이 요구사항이다(계획서 "명령어 설계"). 11/8 기준 런타임 의존성은 0개다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| dataclass + 직접 검증 | 의존성 0개, 오류 메시지를 완전히 통제, pyright strict와 잘 맞음, 설명하기 쉬움 | 검증 코드를 직접 써야 함 |
| pydantic v2 (2.14.3) | 선언만으로 자동 검증, 널리 쓰임 | 의존성 4개(컴파일된 pydantic-core 포함), 줄 번호를 넣으려면 감싸야 함 |
| msgspec (0.22.0) | 의존성 0개, 빠름 | Beta |
| attrs + cattrs | 안정적 | 라이브러리 2개, 이 규모에는 과함 |

## 결정
값은 `@dataclass(frozen=True)`로 표현하고, 파일을 읽을 때의 검증(필수 필드, 타입, 중복, 개수)은 직접 구현한다.

## 이유
추천안(dataclass + 직접 검증)을 채택했다.

## 결과
- 검증 실패는 파일 경로, 줄 번호, 필드, 고칠 방법을 담은 하나의 오류 타입으로 알린다.
- 첫 런타임 의존성 자리는 SQL 파서(D15)에 남긴다.
- 입력 형식이 늘어 검증 코드가 크게 불어나면 이 결정을 다시 본다.
