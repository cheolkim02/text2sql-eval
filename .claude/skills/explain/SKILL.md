# 코드 설명과 면접 연습

대상: $ARGUMENTS

사용자는 면접에서 이 저장소의 모든 줄을 설명해야 한다. 목표는 사용자가 스스로 설명할 수 있게 되는 것이다.

## 1. 설명

대상 파일(또는 폴더 안의 파일)을 끝까지 읽고, 한국어로 아래 순서대로 설명한다.

1. **역할:** 이 코드가 전체 흐름(`예측 파일 → 판정 → 사실 → 비교 → 리포트`)에서 맡는 일 한두 문장
2. **데이터 흐름:** 무엇을 받아 무엇을 돌려주는지, 실제 `examples/bird-mini` 케이스 하나를 예로 들어
3. **선택한 이유와 버린 대안:** 관련 ADR(`docs/decisions/`)이 있으면 번호를 붙여 인용한다
4. **헷갈리기 쉬운 줄:** 타입, 예외 처리, 경계 사례를 다루는 줄을 골라 왜 그렇게 썼는지
5. **테스트:** 이 코드를 지키는 테스트가 어디에 있고 무엇을 검사하는지

용어(예: 판별 유니언, 픽스처, 속성 기반 테스트)는 처음 나올 때 한 줄로 풀어 쓴다.

## 2. 면접식 질문

질문 5개를 낸다.

- 쉬움 2개: 무엇을 하나
- 보통 2개: 왜 이렇게 했나
- 어려움 1개: 다르게 했다면 무엇이 깨지나

질문만 내고 답은 보여주지 않는다. 사용자의 답을 기다린다.

## 3. 채점과 보충

사용자가 답하면 다음을 한다.

1. 질문마다 맞음 / 부분 정답 / 틀림으로 채점한다.
2. 빠진 부분을 보충한다.
3. 모범 답안을 면접에서 말하듯 2~3문장으로 쓴다.

## 4. 저장

문답 전체를 `.study/<모듈 이름>.md`에 추가한다. 이 폴더는 gitignore되어 공개되지 않는다.

- 항목 순서: 날짜, 대상 경로, 설명 요약, 질문, 사용자 답, 채점, 모범 답안
- 같은 파일이 있으면 아래에 이어 쓴다.
